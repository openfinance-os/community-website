# Governance

This document describes how Open Finance OS is organized, how decisions are made, and how the project ensures long-term sustainability.

## Mission

Open Finance OS exists to make the UAE Open Finance ecosystem visible, accessible, and welcoming. We are a grassroots community initiative, independent of any bank, regulator, or official body.

Our goals:
- Provide clear, accurate information about UAE Open Finance
- Lower barriers to understanding and participation
- Foster an inclusive community of practitioners and enthusiasts
- Build open-source tools that benefit the ecosystem

## Roles

### Maintainers

Maintainers are trusted community members who:
- Review and merge pull requests
- Triage issues and discussions
- Ensure content quality and accuracy
- Uphold the Code of Conduct
- Make day-to-day project decisions

Current maintainers are listed in the repository's CODEOWNERS file.

### Contributors

Anyone who contributes to the project through:
- Code or documentation
- Content submissions
- Bug reports or feature suggestions
- Helping others in discussions

All contributors are valued members of the community.

### Community Members

Anyone interested in UAE Open Finance who:
- Uses the website for information
- Participates in discussions
- Shares feedback or ideas

## Decision Making

### Day-to-Day Decisions

Maintainers handle routine decisions independently:
- Merging straightforward PRs
- Fixing bugs and typos
- Minor content updates
- Issue triage

### Significant Decisions

Larger decisions require discussion and consensus:
- New features or major changes
- Content policy updates
- Adding or removing maintainers
- Changes to governance

Process:
1. Open a GitHub Discussion or Issue
2. Allow time for community input (minimum 7 days for major decisions)
3. Maintainers discuss and reach consensus
4. Document the decision and rationale

### Disputes

If maintainers cannot reach consensus:
1. Extend discussion to gather more perspectives
2. Seek input from the broader community
3. If still unresolved, the longest-serving active maintainer makes the final call

## Becoming a Maintainer

Maintainers are added based on:
- Sustained, quality contributions over time
- Demonstrated understanding of project goals
- Positive interactions with the community
- Nomination by existing maintainer and consensus approval

There are no formal requirements or timelines. We look for people who care about the project and community.

## Stepping Down

Maintainers may step down at any time. We ask for:
- Advance notice when possible
- Help transitioning any ongoing work
- Updating access and documentation

Inactive maintainers (no activity for 6+ months) may be moved to emeritus status after outreach.

## Succession Planning

To ensure the project's longevity:

### Repository Ownership
- The GitHub organization has multiple owners
- At least two maintainers should have admin access at all times
- Access credentials are documented securely

### Domain and Infrastructure
- Domain registration details are documented and accessible to multiple maintainers
- Hosting and deployment configurations are documented in the repository
- No single person should be a single point of failure

### Knowledge Transfer
- Key decisions are documented in GitHub Issues/Discussions
- Technical architecture is documented in the repository
- Onboarding new maintainers includes knowledge transfer sessions

## Domain and Assets

### openfinance-os.org

- The domain is held for the benefit of the community
- If the project ends, the domain should not be sold or repurposed for unrelated uses
- Maintainers commit to acting in the community's best interest regarding domain decisions

### Branding

- The Open Finance OS name and logo are used to identify this community project
- They should not be used to imply official endorsement by regulators or financial institutions
- Community members may reference the project with proper attribution

## Funding and Transparency

### Current Model

Open Finance OS operates on volunteer effort. There are currently:
- No commercial sponsors
- No paid maintainers
- No revenue generation

### If Funding Arises

Should the project receive funding in the future:
- Sources will be publicly disclosed
- Funds will be used for project benefit (hosting, domains, etc.)
- Financial decisions require maintainer consensus
- We will not accept funding that compromises independence

### Cost Transparency

Current project costs:
- Domain registration: Covered by maintainers
- Hosting: GitHub Pages (free)
- Other infrastructure: Documented as needed

## Independence

Open Finance OS is:
- **Not** affiliated with CBUAE or any regulator
- **Not** affiliated with any bank or financial institution
- **Not** an official industry body

We are a community of individuals who care about Open Finance. Our opinions and content do not represent any organization.

## Amendments

This governance document may be updated through the significant decision process described above. Changes require:
- A pull request with proposed changes
- Minimum 14-day comment period
- Maintainer consensus
- Clear communication to the community
